# 追問

Agent 問傳承者的時候照這份做。kb-add 用在三個地方：研究前對齊範圍、討論查到的內容、訪談。目標是 Agent 和傳承者對要寫的東西有同樣的理解，再動手寫。

## 先畫一棵樹

要問清楚的事有先後：前面的定了，後面的才問得準。把它們排成一棵樹，根是這次要寫的主題，每個答案再長出接下來要問的事。

**前線**是前提都已經定了、現在就能問的題目。一題的答案要看同一輪另一題怎麼回，就留到下一輪。

## 一輪怎麼問

- 一輪只問前線，最多五題，最根本的先問。
- 每題編號，附上你的建議答案或猜測，數字也猜一個（例如「大概三個月一次？」）。問法要讓傳承者回「好」就等於接受建議，比從零回答省力。建議和猜測只用來問；寫進簡報頁的，是傳承者說的或出處寫的。
- 查得到的事自己查，不問人：已有的頁怎麼寫（`read.py --find`）、數字和出處、名詞的意思。要問傳承者的，只有判斷和只在傳承者腦袋裡的經驗。
- 有問答工具（例如 Claude Code 的 AskUserQuestion）就用：一次最多四題，第一個選項放建議答案，傳承者也可以自己打字改正。要附出處、說明很長的題目（例如討論查到的內容），或沒有問答工具時，改用編號文字：

  ```
  Q1 讀者是誰：……
  ➡️ 建議：……
  ```

  傳承者回「Q2 不對，是……」就好。
- 傳承者回答之後，看哪些題目定了、哪些新題目可以問了，算出下一輪的前線。

## 追問

- 傳承者說的和出處、已有的頁不一樣時，指出來：哪一頁（頁 id）、哪一句、各自的依據，問哪個對。由傳承者決定，照傳承者決定的寫，不另外留紀錄。
- 傳承者說已有的那一頁才是錯的：照常做完這次的提案；開好之後，問要不要接著用 kb-change 改那一頁。
- 每一章至少問一次：「新人最常誤會什麼？」「什麼情況下這個說法不成立？」答案常常就是新人最需要的那一句。

## 什麼時候停

- 樹上每個分支都問過，你能用自己的話講給新人聽，傳承者也同意，就停。
- 傳承者說「夠了」也停。還沒問清楚的內容，不寫進簡報頁。
- 傳承者沒空：停下來，等傳承者回到對話再接著問。不留言、不另外存檔。
