# 讀者測試

開變更提案之前做，找出新人讀不懂的地方：寫的人覺得清楚，沒有背景的人不一定看得懂。

1. **出題**：`python3 framework/tools/reader_test.py <知識庫>`。它找出這個分支改過的章（只改了開頭的速覽、先修不算），每一章產生一份題目卷和一份答案卷：題目卷是那一章每一頁的文字、深入頁的說明和旁白。互動圖讀者看不到，所以測的是文字、說明和旁白講不講得清楚。
   讀者讀整章，但只考這次有關的題目：「相關：」指到改過的頁的自我檢查，和這次新增或改過的題目。深入題不考。改過的頁沒有題目時它會停下來；用 `--ask "<頁 id>：<題目>"` 替每一頁補一題「讀完應該答得出來」的題目，再跑一次。
2. **外行讀者作答**：每一章開一個子 agent（Agent 工具），只跟它說「讀 <題目卷>，照裡面的指示作答」。題目卷已經寫好外行讀者的指示，也拿掉了題目的答案；多給別的資料或提示，測出來就不準了。
3. **對答案**：拿它的回答對照答案卷。答不出來、答錯、或用了章裡沒有的知識，都算沒過。
4. **改寫**：沒過的地方通常是術語沒解釋、跳了一步、缺了「為什麼」。改寫後從第 1 步再測一次。

完成：題目卷上的題目全部答對，答案寫在哪一頁都一樣。這些題目是因為「相關：」指到這次改過的頁才被選進來，答不出來就不能開提案，也不能說成舊題：把那一頁、或答案所在的頁寫清楚，再測一次。

例外是舊缺口：答案本來就不在任何簡報頁（只寫在自我檢查的答案裡，或根本沒寫），不是這次改壞的。用 `read.py <知識庫> <頁id>` 讀正式內容確認。這時先問維護者，Agent 不能自己放行：維護者同意，就開一個待回答或勘誤 issue 追蹤，提案說明照實寫「讀者測試：n/m 題答對」，加上沒過的題目、原因和 issue 編號。開提案時用 `proposal.py … --reader <n/n>` 把結果寫進說明。

## 舊題答不出來

這裡的舊題，是題目卷上沒有的題目：它們和這次改的頁無關，答不出來是以前就有的問題，不擋這次，也不要混進這次的提案。想看整章的狀況時，加 `--all` 把整章的題目都考一次；答不出來的舊題開成一個 issue（標籤：勘誤、kb:<知識庫>），列出題目和相關的頁，之後一題一題改。
