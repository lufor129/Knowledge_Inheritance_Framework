# 手冊的格式與寫作

寫或改手冊時照這份做；出處、圖片、術語表、ELI5 這幾段，簡報頁也照這裡。新人主要看簡報：新知識先做成簡報頁（framework/guide/deck.md），一頁放不下的細節才寫進手冊。用詞照 GLOSSARY.md；檔案骨架在 framework/templates/。

## 結構

- **部分**是 `kb/<名稱>/handbook/` 底下的資料夾，名稱「數字-英文」（例如 `2-manufacturing`），裡面的 README.md 第一行寫 `# 部分名稱`。部分只用來分組。
- **章**是部分裡的一個檔案，名稱「兩位數字-英文.md」（例如 `05-gate.md`），第一行寫 `# 章名`。一章一個主題。
- **小節**是章裡的一個概念，開頭兩行固定：

  ```
  <a name="hk1"></a>
  ## 閘極絕緣層
  ```

  小節內容格式自由。

## 小節 id

- 小寫英文開頭，後面接小寫英文或數字，簡短好打（例如 `hk1`、`litho6`、`ocd`）。在同一個知識庫裡不能重複。
- 建立後**永遠不改名**。要改的是標題和內容，id 不動。
- 刪除或合併小節時，所有引用（常見問題的「相關：」、頁序、其他小節、其他知識庫）在同一個變更提案裡一起改掉，不留舊 id。找引用：`git grep -n "<id>" -- kb/`。
- 跨知識庫引用寫成 `知識庫名稱/id`，例如 `semiconductor/hk1`。

## 每一章的順序

1. `# 章名`
2. **速覽**（建議有）：`> 速覽：` 開頭，三五句話講這章在講什麼、讀完會懂什麼。
3. 各小節。
4. **常見問題**（有題目才建），放在最後，標題固定 `## 常見問題`：

   ```
   <details>
   <summary>電晶體會壞嗎？可以用多久？</summary>
   正常使用可以用十年以上……
   相關：hk1、wat
   </details>
   ```

   - 答案收在 `<details>` 裡，讓新人先自己想。先講結論，再講原因。
   - 每題最後一行寫 `相關：` 加上小節 id，用「、」分隔。答案裡的說法要在這些小節裡找得到：常見問題是複習用的摘要，知識本身寫在小節裡。
   - 給有業界經驗的人的題目是**深入題**：題目前加 `【深入】`，排在常見問題的最後。
   - 手冊裡只放有答案的題目。還沒有答案的問題是 issue（待回答），不寫進手冊；只有手動模式例外，寫成 `<summary>【待回答】題目</summary>`。

## 出處

- 每個數字、每個「研究指出」都要附出處註腳。註腳名稱用「小節 id-編號」，在同一章裡不重複：

  ```
  牆每薄 0.2 nm，漏電大約多 10 倍[^hk1-1]。

  [^hk1-1]: 出處：論文、文件位置或網址
  ```

- 註腳定義寫在那一節的最後。
- 出處的寫法：
  - 論文寫作者、標題、期刊、年份或 DOI；網頁寫標題和網址。
  - 新聞、業界媒體、部落格是報導，寫「出處（報導）：媒體，標題，日期，網址」。先找第一手來源（原廠文件、論文、官方網頁），找不到才用報導；標出來，讀者和維護者才知道這個說法有多可靠。
  - 公司文件寫文件名稱和放在哪裡。
  - 訪談寫「口述的人（部門）口述，YYYY-MM」。
- 找不到出處的數字就不寫，或改成不帶數字的說法。不要編出處。
- 整理別人的資料時，原檔不放進知識庫，只在出處寫明它在哪裡。

## 圖片

- 圖片放在 `kb/<名稱>/assets/img/`，在手冊裡寫 `![說明](../../assets/img/檔名.jpg)`。
- 每張圖片都要列進 `assets/SOURCES.md`：檔名、說明、出處。不在清單上的圖片不能用。只寫出處，不用寫授權。

## 術語表

- `kb/<名稱>/terms.md` 一列一個術語：中文、英文、一句話解釋、第一次出現在哪一節。
- 新增知識時，有新術語就順便加一列。

## 寫作：ELI5

讀者是沒有背景的新人。方向是 ELI5，要多白話由內容決定：

- 先講白話，再講術語。術語第一次出現附英文，例如「量子穿隧（Quantum Tunneling）」。
- 能用生活比喻就用一個。
- 一個小節講一個概念；先講「為什麼要知道這個」，再講細節。
- 寫得清不清楚，由讀者測試判斷（framework/guide/reader-test.md），不是靠這份清單。
