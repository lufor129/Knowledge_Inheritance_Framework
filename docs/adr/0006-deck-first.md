# 新人以簡報為主：簡報必備、手冊選配，兩邊一樣重要

> 2026-10-26：手冊拿掉了，「手冊選配、兩邊一樣重要、雙向指紋」改由 ADR-0007 決定；其他照舊。

2026-10-25 定案，取代 ADR-0002。互動和圖像比長文好吸收，所以新人主要看簡報，從入口網站開始。每個知識庫都要有簡報，每個小節都要有簡報頁講到；簡報頁也可以講手冊沒寫的。新知識先做成簡報頁，一頁放不下的細節（推導、表格、很多出處）才寫手冊小節。

簡報和手冊一樣重要：查找時兩邊都算出處；說法不同時，兩種都列出來，問要不要記成勘誤。頁序記下簡報頁和對應小節兩邊的指紋，哪一邊改了，檢查程式就點名另一邊要重看。簡報頁的文字寫在 Markdown（`deck/<部分>/<章>.md`），互動圖寫在程式裡，查找、搜尋、讀者測試和檢查才讀得到文字。

## Considered Options

- **維持手冊是正本、簡報選配（ADR-0002）**：說法只有一個標準答案，但新人主要看的東西不是正本，簡報講到、手冊沒寫的內容查不到，也沒人審。
- **每一頁都要對應小節，現有沒有對應的頁補成手冊**：內容全部有手冊撐著，但半導體有 68 頁要先補寫手冊，傳承者做新內容也要寫兩份。
- **簡報當正本、手冊由簡報產生**：只有一份，不會不一致；但長的推導、表格、很多出處放不進一頁，現有 28 個小節也要整個搬過去。

## Consequences

- 兩份文字可能不一致，所以指紋改成雙向；說法不同時兩種都給新人看，由勘誤收斂。
- 簡報頁上新寫或改到的說法，數字一定要附出處，檢查程式會擋；原本就有的說法（包括搬進來的舊頁）先豁免，補出處列成傳承者可以慢慢做的工作（`index.py --todo`）。管到句子、不管到整頁：測試裡修一個數字，整頁都要補出處時，Agent 為了過檢查刪掉了三句找不到出處的舊說法，小修正變成整頁重寫。
- 讀者測試也測簡報：只給簡報那一章的文字和旁白。互動圖讀者看不到，所以要讓新人讀的文字都寫在 Markdown（重點、圖說、旁白），互動圖只畫圖。
- 部分和章由簡報決定，手冊用同樣的編號；新知識庫的骨架一開始就有簡報。
