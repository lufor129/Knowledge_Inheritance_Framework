# 修改、刪除、合併

格式與寫作照 framework/guide/writing.md；Git 主機的操作照 framework/guide/host.md。

## 照維護者的意見改

使用者說「照維護者的意見改」這類話時：

1. 找到他的變更提案（目前的分支，或問他編號），讀維護者的意見：`gh pr view <N> --comments` 和審查意見。
2. `gh pr checkout <N>`，照意見逐條改。看不懂或不同意的意見，先問使用者。
3. 跑下面的第 6、7 步（檢查、讀者測試），commit、推上去。同一個提案繼續用，不開新的。
4. 在提案上留言，逐條說明每個意見怎麼處理的。

## 修改、刪除、合併

1. **開分支**：從最新的 main 開。修正勘誤時先讀 issue，確認是哪一節、哪一句、依據是什麼。
2. **找出要動的小節**：用 `python3 framework/tools/index.py <知識庫>` 和 grep。說不清楚是哪一節就問使用者。
3. **列出所有引用**：`grep -rn "<id>" kb/`：常見問題的「相關：」、頁序 deck/order.md、其他小節、其他知識庫（寫成 `<知識庫>/<id>`）。清單給使用者看。
4. **改**：
   - **修改**：改內容，id 不動。數字附出處；修正勘誤時，新的出處一起補上。
   - **刪除**：刪掉小節，引用一個一個處理：改指到別的小節、跟著刪、或從簡報頁拿掉這個對應。
   - **合併**：把 B 併進 A，保留 A 的 id；所有指向 B 的引用改成 A，再刪掉 B。舊 id 不留。
   刪掉的內容 Git 歷史找得回來。
5. **傳承者確認**：用白話給他看改了什麼、哪些引用一起改了。他明確說好才往下走。
6. **檢查**：`python3 framework/tools/check.py <知識庫>`，到沒有 ✗ 為止；被點名的簡報頁照 framework/guide/deck.md 處理。
7. **讀者測試**：照 framework/guide/reader-test.md，測改過的章；刪除時，測受影響的常見問題還答不答得出來。
8. **開變更提案**：說明的「影響」列出一起改的引用和簡報頁；修正勘誤時寫 `Closes #N`；來歷照新內容怎麼來的。之後照 host.md「開好之後」做。
