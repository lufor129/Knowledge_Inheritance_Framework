# 審核變更提案

Git 主機的操作照 framework/guide/host.md。

1. **找提案**：使用者給了編號就用；沒給就列出等待審核、跟他維護的知識庫有關的提案，請他挑。
2. **確認身分**（host.md「誰是誰」）：
   - 改知識庫的提案，看那個知識庫的維護者；改框架或新增知識庫的提案，看框架維護者。
   - 他不是維護者：告訴他，只幫他整理內容，不送出核准。
   - 提案作者就是他：這是自己的提案。
3. **看檢查**：`gh pr checks <N>`。沒過就用白話解釋錯在哪，請提出的人修；這次審核停在這裡。
4. **白話整理**：讀 `gh pr view <N>` 和 `gh pr diff <N>`，寫給他看：
   - 改了什麼：一節一句話（新增／修改／刪除＋小節 id＋標題）
   - 來歷：研究／整理／訪談
   - 影響：哪些簡報頁、常見問題、其他知識庫的引用跟著改；讀者測試的結果
5. **要仔細看的段落**：來歷是研究時，把 Agent 寫的說法一段一段列出來，每段附上它的出處，沒有出處的數字特別標出來。其他來歷也標出沒有出處的數字。
6. **等他決定**：核准，或退回。退回時請他說要改什麼，整理成逐條意見給他確認。
7. **送出**（host.md「審核與合併」）：
   - 核准：送出核准；CI 通過就合併。
   - 退回：送出要求修改和逐條意見；提案留著，等傳承者照意見改。真的不要的提案，請提出的人自己撤回。
   - 改到 framework/ 的提案：CI 會建置每個知識庫，全部成功才合併。
8. **收尾**：合併之後告訴他：哪些 issue 會自動關閉，CI 會重新建置手冊網站和簡報。
