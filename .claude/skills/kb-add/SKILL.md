# 新增知識

主要目標是**新人好吸收**：資料正確只是起點，新人看一遍就懂才算做完。怎麼做見 framework/guide/deck.md 的「新人好吸收」。

## 開工：有什麼可以回答

使用者問「有什麼我可以做的」「有什麼我可以回答的」這類問題時：

1. `python3 framework/tools/who.py`：看使用者的名字和關心的知識庫。還沒記的就問，用 `who.py --set name=<名字> watch=<知識庫>,<知識庫>` 記下來，下次就不用再問。
2. 列出那些知識庫開啟中的待回答和勘誤：`gh issue list --state open --label kb:<知識庫> --json number,title,labels,assignees`。每題寫編號、題目、種類、有沒有人認領。
   再列出簡報裡數字還沒有出處的頁：`python3 framework/tools/index.py <知識庫> --todo`。這些沒有期限，挑一頁補出處就是一個變更提案（走 kb-change）。
   最後告訴使用者怎麼開始：說「我來回答 #N」認領一題，或說要補哪一頁的出處。
3. 使用者說「我來回答 #N」：`gh issue edit <N> --add-assignee @me`，再留言「🤖 由 Agent 產生」加「<名字> 認領」，讓別人知道這題有人在寫。然後從下面第 1 步開始，目標就是回答這一題。勘誤的修正走 kb-change。

## 新增

步驟多，開始前用 TodoWrite 列出下面九步，做完一步勾一步。

1. **開分支**：`git fetch origin && git switch -c kb/<知識庫>/<簡短英文> origin/main`。從最新的正式內容開，才不會和別人的改動打架。
2. **決定方式**，不確定就問：
   - **研究**：使用者只給主題。
   - **整理**：使用者給了資料（檔案、網址、舊簡報、照片）。
   - **訪談**：使用者要口述經驗，或答案只在使用者腦袋裡。
3. **蒐集**：
   - 研究：先列出新人需要知道的三到七個重點，請使用者確認範圍再查。研究最花時間和費用，先對齊範圍才不會查了用不到的東西。每個重點找一兩個第一手來源（官方文件、論文、原廠網頁）確認就夠；只找得到新聞或業界媒體的，註腳標「出處（報導）」（寫法見 writing.md）；什麼都找不到的數字不寫。
   - 整理：讀完資料，挑出新人需要的部分改寫成白話。原檔不放進知識庫，出處寫明它在哪裡。看不懂或互相矛盾的地方記下來問使用者。
     材料裡有圖就主動挑：`python3 framework/tools/image.py extract <材料檔>` 取出圖片，一張一張看，把新人一看就懂的圖和流程圖推薦給傳承者，說明每張好懂在哪裡，由傳承者選。公司內部資料不放。授權和放法見 writing.md 的「圖片」。
   - 訪談：一輪問三到五題，編號，每題附上你的猜測，數字也猜一個（例如「大概三個月一次？」），讓傳承者回「對」或改正就好，比從零回答省力。猜測只用來問，寫進去的是傳承者說的。一直問到你能用自己的話講給新人聽、傳承者也同意為止。傳承者沒空當面講，就把題目寫成一則留言（回答 issue 時留在那個 issue 上），等有空再回。出處寫「名字（部門）口述，YYYY-MM」。

   完成：每個要寫進簡報頁的說法，都指得出來源（文件、網址或口述的人）。
4. **找位置**：`python3 framework/tools/index.py <知識庫>`。
   - 新內容放進最相關的章（章檔 `deck/<部分>/<章>.md`；先看 index.py 列的每章速覽），一章一個變更提案，維護者才審得動。
   - 回答待回答時，答案寫進簡報頁（已有的或新的主頁、深入頁），再在那一章的「## 自我檢查」加一題，「相關：」連到那一頁。讀者測試的題目卷只有頁的文字、說明和旁白，答案只寫在題目裡就答不出來。
   - 跟已有的頁重複時，改成修改那一頁（kb-change）。
5. **做簡報頁**：照 framework/guide/deck.md。新人主要看簡報，所以先想新人在這一頁看到什麼：
   - 一頁一個概念：結論、三到四點重點、數字卡、比喻、旁白；數字附出處註腳（寫法見 writing.md）。新的頁取新的頁 id，加進頁序 `deck/order.md`。
   - 圖：流程、會動、會變、有因果的概念，預設做成可以操作的互動圖，深入頁也一樣；先套樣板（`framework/engine/figures/templates.js`），套不上才自己寫。材料裡有好懂的圖或流程圖時，先放那張（`image.py add`），不要重畫；上面是英文也沒關係，圖說寫中文就好。要不要另外做成互動圖，問傳承者。其他可以用圖片、圖表。
   - 一頁放不下時（較長的推導、表格、很多出處，或口述的細節比一頁多很多），建議做成接在後面的深入頁，由傳承者決定：寫「- 深入：<主頁 id>」，長文寫在「說明：」，頁序裡緊接在主頁後面（寫法見 framework/guide/deck.md）。
   - 新的一章：章檔開頭寫速覽（兩三句：學完會知道什麼、為什麼排在這裡）和圖示（從 framework/guide/deck.md 的圖示表挑一個）；真的要先看過別的章才看得懂，再寫先修。
   - 有新術語就在 terms.md 加一列；建議在那一章的「## 自我檢查」替新的頁加一題。
6. **傳承者確認**：先自己照 deck.md 的「新人好吸收」看一遍，沒做到就先改，不要把表格初稿交出去等傳承者提醒。再用白話講改了什麼。交稿的訊息一定要有一段「為了新人好吸收，我這樣做」，列出這次的設計（例如流程做成一步步播放的圖、這個詞先白話解釋、哪張材料圖為什麼選它）；材料裡的圖列給傳承者選，等傳承者選了才算數。打開做好的頁給傳承者看：`python3 framework/tools/get.py <知識庫> deck --here --open --page <頁id>`。標出你不確定的地方，照傳承者的意見改。內容是傳承者的經驗，所以傳承者明確說好才往下走。
7. **檢查**：`python3 framework/tools/check.py <知識庫>`，到沒有 ✗ 為止。
   - 這次新寫或改到的說法（結論、重點、圖說、數字卡、深入頁說明的每一段），數字沒附出處會擋：補出處，或改成不帶數字的說法。
   - 新寫的旁白、自我檢查答案有數字沒出處、出處看不出是真的來源、互動圖裡寫了數字，檢查會用 △ 提醒。一樣補上；留著的話，簡報上會標「待查證」，開提案時告訴傳承者。
8. **讀者測試**：照 framework/guide/reader-test.md（讀者讀整章，只考和改過的頁有關的題目），全部答對才往下走。
   第 6 步之後又補了說法（例如為了讓讀者測試答得出來，多寫一段），開提案前把補的部分再給傳承者看一次，傳承者說好才算數。
9. **開變更提案**：commit 之後跑 `python3 framework/tools/proposal.py <知識庫> --source <研究|整理|訪談> --reader <n/n>`；回答 issue 時加 `--closes <N>`，合併後那個 issue 才會自動關閉。它會寫好說明的草稿 `.kif/tmp/proposal.md`：把「（……）」換成你的話，標題換成一句話，然後照它印出的指令推分支、開提案，再做「開好之後」那一步。

完成：頁面新人看一遍就懂，傳承者說好了；提案開好了，使用者知道提案編號、在等誰審，以及合併後哪個 issue 會自動關閉。使用者要在這次對話裡合併時，先留審核紀錄（framework/guide/host.md）。
