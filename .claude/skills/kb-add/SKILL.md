# 新增知識

格式與寫作照 framework/guide/writing.md；Git 主機的操作照 framework/guide/host.md。

## 開工：有什麼可以回答

使用者問「有什麼我可以回答的」這類問題時：

1. 從 `.kif/local.json` 讀他的名字和關心的知識庫；沒有就問，問完記下來（`{"name": "老王", "watch": ["semiconductor"]}`）。
2. 列出那些知識庫開啟中的待回答和勘誤 issue：編號、題目、種類、有沒有人認領。
3. 他說「我來回答 #N」：指派給他、留言認領，然後從下面第 1 步開始，目標就是回答這一題。勘誤的修正走 kb-change。

## 新增

1. **開分支**：從最新的 main 開。
2. **決定方式**，不確定就問：
   - **研究**：使用者只給主題。
   - **整理**：使用者給了資料（檔案、網址、舊簡報、照片）。
   - **訪談**：使用者要口述經驗，或答案只在他腦袋裡。
3. **蒐集**：
   - 研究：先列出新人需要知道的重點，再找第一手來源（官方文件、論文、原廠網頁）逐一確認。每個數字都要有出處，找不到出處的數字就不寫。
   - 整理：讀完資料，挑出新人需要的部分改寫成白話。原檔不放進知識庫，出處寫明它在哪裡。看不懂或互相矛盾的地方記下來問使用者。
   - 訪談：一輪問三到五題，編號，每題附上你的猜測，讓他回「對」或改正就好。一直問到你能用自己的話講給新人聽、他也同意為止。他沒空當面講，就把題目寫成一則留言（回答 issue 時留在那個 issue 上），等他有空再回。出處寫「名字（部門）口述，YYYY-MM」。
4. **找位置**：`python3 framework/tools/index.py <知識庫>` 看現有的部分、章、小節。
   - 新內容放進最相關的章，一章一個變更提案。
   - 回答待回答時，通常寫成那一章常見問題的一題，需要時再補一個小節。
   - 跟已有的小節重複時，改成修改那一節（kb-change）。
5. **寫草稿**：照 writing.md。新小節取新的 id；有新術語就在 terms.md 加一列。
6. **傳承者確認**：用白話給他看草稿（`git diff`），標出你不確定的地方，照他的意見改。他明確說好才往下走。
7. **檢查**：`python3 framework/tools/check.py <知識庫>`，到沒有 ✗ 為止。
   - 被點名的簡報頁照 framework/guide/deck.md 處理。
   - △ 提醒（數字沒出處）要補出處或改寫；真的補不了，在提案說明裡寫出來。
8. **讀者測試**：照 framework/guide/reader-test.md，全部答得出來才往下走。
9. **開變更提案**：commit、推分支、開提案，說明寫來歷；回答 issue 時寫 `Closes #N`。之後照 host.md「開好之後」做。
