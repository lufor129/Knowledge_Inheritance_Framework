# 學習

查找和帶讀只用**正式內容**：主線上最新的手冊。分支上還沒合併的內容、簡報、你自己的知識都不算，因為新人要學的是維護者審核過的說法。`read.py` 和 `index.py --main` 讀的就是正式內容，會先抓最新的主線。

## 查找

1. **找候選**：`python3 framework/tools/index.py --main <知識庫>` 看小節標題、常見問題和術語；再用 `python3 framework/tools/read.py <知識庫> --find <字> <字>` 找內文，中文、英文、縮寫都試。不確定是哪個知識庫，`index.py --main` 不加名稱就是全部。
2. **讀完候選**：`read.py <知識庫> <小節id> <小節id>`；常見問題用 `read.py <知識庫> --faq <字>`。
3. **回答**：先一句話答案，再補細節，用白話；只寫讀到的內容。
4. **出處**：最後列「出處：<知識庫> › <章> › <小節 id>」，用到幾節列幾節；read.py 每一段的開頭就是這個格式。用到常見問題時，列它「相關：」的小節。
5. **沒寫到**：手冊沒寫，或只寫到一部分，就直說「手冊沒有寫到……」，然後問「要記成待回答嗎？」，接「回報」。

完成：回答的每一句都指得出是哪一節寫的。

## 帶讀

使用者想讀一章、一節，或說「再講細一點」「考考我」時：

1. 講這一節在講什麼、為什麼要知道。用 ELI5，用手冊裡的比喻。
2. 請使用者用自己的話講一次，或問一個「為什麼」，看懂到哪。
3. 出一題選擇題：三個選項長度差不多，正確答案的位置每題換，免得猜得到。等使用者答了再公布，說明為什麼，並指回小節。
4. 答錯就換個說法再講、再出一題。

學習紀錄只留在對話裡。

## 回報：手冊沒寫、寫錯

1. **分種類**：手冊沒寫 → 待回答；手冊寫的跟使用者知道的不一樣 → 勘誤。勘誤要問清楚：哪一節、哪一句、為什麼覺得不對、依據是什麼，傳承者才查得下去。
2. **查重複**：`gh issue list --state all --label <待回答|勘誤> --search "<關鍵字>"`，換兩三組關鍵字（中文、英文、縮寫）。有一樣的就在那個 issue 留言（「我也想知道」或補充依據），告訴使用者編號，不開新的。
3. **開 issue**：沒有重複就問「要記下來嗎？」。使用者說好，把內文寫進 `.kif/tmp/issue.md`，第一行「🤖 由 Agent 產生」，再開：`gh issue create --title "<題目>" --label <待回答|勘誤> --label kb:<知識庫> --body-file .kif/tmp/issue.md`
   - 待回答的內文：問題、新人當時在讀哪一章（猜的就寫「猜的」）、誰問的（名字用 `python3 framework/tools/who.py` 查，還沒記就問）。
   - 勘誤的內文：小節 id、那一句原文、為什麼覺得不對、依據。
4. **告訴使用者**：issue 編號，以及傳承者回答、合併之後，issue 會自動關閉，使用者會收到通知。

GitLab 和沒有 Git 主機的手動模式，照 framework/guide/host.md。

## 打開手冊網站或簡報

1. `python3 framework/tools/get.py <知識庫> deck --open`（手冊網站把 deck 換成 handbook）。它會先從 Git 主機下載最新發布的，下載不到就在本機建置。
2. 第一次看的人，告訴對方建議的順序：**先**看手冊網站首頁的全景圖和各章速覽，知道整個領域長什麼樣、每章在講什麼；**再**看簡報，從議程那一頁開始。先有全貌，後面每一章才知道放在哪裡。要的話也幫忙打開手冊網站。
