# 學習

查找和帶讀只用**正式內容**：主線上最新的簡報（主頁、深入頁、自我檢查）。分支上還沒合併的內容、你自己的知識都不算，因為新人要學的是維護者審核過的說法。`read.py` 和 `index.py --main` 讀的就是正式內容，會先抓最新的主線。

## 查找

1. **找候選**：`python3 framework/tools/index.py --main <知識庫>` 看每章的速覽、簡報頁、自我檢查和術語；再用 `python3 framework/tools/read.py <知識庫> --find <字> <字>` 找內文，中文、英文、縮寫都試。不確定是哪個知識庫，`index.py --main` 不加名稱就是全部。
   使用者貼來「我在看〈知識庫〉簡報的〈標題〉這一頁（頁 id：…），想問：…」：先讀那一頁，再從那一頁出發找答案。
2. **讀完候選**：`read.py <知識庫> <頁id> …`。主頁會列出接在後面的深入頁，長說明、推導和出處常常在深入頁，一起讀；自我檢查用 `read.py <知識庫> --faq <字>`。
3. **回答**：先一句話答案，再補細節，用白話；只寫讀到的內容。兩頁說法不同時，兩種都講，說清楚哪裡不一樣，再問「要記成勘誤嗎？」，接「回報」。
4. **出處**：最後列出處，用到幾頁列幾頁，照 read.py 每一段開頭的格式抄：「<知識庫> › 簡報 › <章> › 〈頁標題〉（頁 id）」。用到自我檢查時，列它「相關：」的頁。
5. **沒寫到**：簡報沒寫，或只寫到一部分，就直說「簡報沒有寫到……」，然後問「要記成待回答嗎？」，接「回報」。

完成：回答的每一句都指得出是哪一頁寫的。

## 帶讀

使用者想讀一章、一頁，或說「再講細一點」「考考我」時：

1. 講這一頁在講什麼、為什麼要知道。用 ELI5，用簡報頁的比喻和旁白；使用者想知道更多時，接著講後面的深入頁。
2. 請使用者用自己的話講一次，或問一個「為什麼」，看懂到哪。
3. 出一題選擇題：三個選項長度差不多，正確答案的位置每題換，免得猜得到。等使用者答了再公布，說明為什麼，並指回那一頁。
4. 答錯就換個說法再講、再出一題。

學習紀錄只留在對話裡。

## 回報：沒寫、寫錯

1. **分種類**：簡報沒寫 → 待回答；簡報寫的跟使用者知道的不一樣，或兩頁說法不同 → 勘誤。勘誤要問清楚：哪一頁、哪一句、為什麼覺得不對、依據是什麼，傳承者才查得下去。
2. **查重複**：`gh issue list --state all --label <待回答|勘誤> --search "<關鍵字>"`，換兩三組關鍵字（中文、英文、縮寫）。有一樣的就在那個 issue 留言（「我也想知道」或補充依據），告訴使用者編號，不開新的。
3. **開 issue**：沒有重複就問「要記下來嗎？」。使用者說好，把內文寫進 `.kif/tmp/issue.md`，第一行「🤖 由 Agent 產生」，再開：`gh issue create --title "<題目>" --label <待回答|勘誤> --label kb:<知識庫> --body-file .kif/tmp/issue.md`
   - 待回答的內文：問題、新人當時在看哪一頁或哪一章（猜的就寫「猜的」）、誰問的（名字用 `python3 framework/tools/who.py` 查，還沒記就問）。
   - 勘誤的內文：頁 id、那一句原文、為什麼覺得不對、依據。兩頁說法不同時，兩頁的原文都附上。
4. **告訴使用者**：issue 編號，以及傳承者回答、合併之後，issue 會自動關閉，使用者會收到通知。

GitLab 和沒有 Git 主機的手動模式，照 framework/guide/host.md。

## 打開入口網站或簡報

1. 新人從入口網站開始：`python3 framework/tools/get.py portal --open`。它會先從 Git 主機下載最新發布的入口網站，下載不到就在本機建置。
2. 第一次看的人，告訴對方怎麼用：挑一個知識庫，先看全景圖和每章的速覽，再照學習路徑看簡報；每頁下面的「旁白」打開講解，「看深入」翻到後面的深入頁（可以跳過），「問 Agent」複製這一頁的位置，貼過來就能接著問；每章最後有自我檢查。看過的頁會記在自己的瀏覽器裡，入口網站會打勾。
3. 只要一份簡報：`python3 framework/tools/get.py <知識庫> deck --open`，要直接打開某一頁加 `--page <頁id>`。
