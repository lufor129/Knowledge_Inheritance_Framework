# 學習

## 只讀正式內容

查找和帶讀只用 main 上的手冊。先 `git fetch origin`；目前不在 main，或 main 落後時，用 `git grep <字> origin/main -- kb/` 和 `git show origin/main:<檔案>` 讀，分支上還沒合併的內容不算。

## 查找

1. `python3 framework/tools/index.py <知識庫>`，從小節標題、常見問題、術語找候選，再用 grep 找內文。
2. 打開候選小節讀完，只根據讀到的內容回答：先一句話答案，再補細節，用白話。
3. 最後寫出處：「出處：<知識庫> › <章> › <小節 id>」，用到幾節列幾節。
4. 手冊沒寫到，或只寫到一部分：直說「手冊沒有寫到……」，然後問「要記成待回答嗎？」，接「回報」。

完成：回答的每一句都指得出手冊裡的依據。

## 帶讀

使用者想讀一章、一節，或說「再講細一點」「考考我」時：

1. 講這一節在講什麼、為什麼要知道。用 ELI5，用手冊裡的比喻。
2. 請他用自己的話講一次，或問他一個「為什麼」，看他懂到哪。
3. 出一題選擇題：三個選項長度差不多，正確答案的位置每題換。等他答了再公布，說明為什麼，並指回小節。
4. 答錯就換個說法再講、再出一題。

學習紀錄只留在對話裡。

## 回報：手冊沒寫、寫錯

1. **分種類**：手冊沒寫 → 待回答；手冊寫的跟他知道的不一樣 → 勘誤。勘誤要問清楚：哪一節、哪一句、為什麼覺得不對、依據是什麼。
2. **查重複**（host.md）。有一樣的 issue：在那裡留言「我也想知道」或補充依據，告訴他編號。
3. **開 issue**：沒有重複就問「要記下來嗎？」，他說好就開，貼種類和 `kb:<知識庫>` 標籤。待回答猜一下屬於哪一章，寫明是猜的。
4. 告訴他編號，以及：傳承者回答、合併之後，issue 會自動關閉，他會收到通知。

沒有 Git 主機時，照 host.md 的手動模式做。

## 打開手冊網站或簡報

1. 從 Git 主機下載最新的（host.md「下載」），用 `open` 打開。
2. 下載不到時（沒有主機、沒網路、還沒發布）：`python3 framework/tools/build.py <知識庫>`，打開 `kb/<知識庫>/dist/` 裡的檔案。
3. 第一次看的人，提醒他先看全景圖和各章速覽：兩個都在手冊網站的首頁；簡報從議程那一頁開始看。
